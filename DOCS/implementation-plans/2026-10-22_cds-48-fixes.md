# Implementation plan: CDS-48, the fixes from the Phase 5 review

**Goal.** Fix the 2 Blockers and 15 Changes accepted at the owner's sign-off (review record `.review/2026-10-22_cds-48-phase-5-review.md`, section 7), plus Notes N-3 and A-14. Each fix is test-first and mutation-proved; where a probe cannot show it, say so plainly. After the fixes, a confirmation pass by one fresh reviewer (review plan decision D4) checks the fixes and what they could have broken. Then DR-068, the records, and the closure (`close-project`).

## What is fixed, in five slices (one pull request each, in this order)

**Slice 1: the proof and the registry** (`claude/cds-48-fix-proof`).
- **A-01 (Blocker).** `safeRedirect.ts`: with the flag on, an absolute or protocol-relative target is followed with `window.location.assign`. The `@ui` step "Alex is back on the credit card's own page" first checks that the page's origin is the site's, and fails with a message of its own ("the browser left the site: its origin is '…'"). The registry's `failsWith` becomes that text, so a broken Cancel button can no longer produce it. Gherkin sentences do not change; only the step's implementation and message do (decision D4). In CI the external address does not resolve, so the page ends on a Chromium error page, and the check does not depend on the network.
- **A-02, B-08.** `schema-check.mjs` rejects a `failsWith` that is too generic (a minimum length and a deny-list: `Expected`, `AssertionError`, `Timeout of`, and a bare image name). The Vitest test name is anchored and the proof requires exactly one test ran. A visual catcher is reported as a separate "page changed" kind that does not count alone towards "caught for the stated reason" (`verdict.ts`, the proof table, UI specification section 9).
- **A-03, B-01 (the proof part).** The proof table (`bug-flags.json` and `.md`) keeps each catcher's matched failure line. Artifact retention is 90 days. The `ci.yml` comment and harness design section 37 are corrected. (The durable committed copy is in slice 5.)
- **A-08, B-09.** The `flags` job is pinned to `ubuntu-24.04`.
- **A-09, B-10.** Run limits sit below the job limits (flags 25 minutes). The table is written after each flag. The log upload runs on `failure() or cancelled()`.
- **A-14.** The proof passes a Vitest timeout for component catchers.
- *Proofs.* Unit tests for the verdicts, the generic-text rejection and the anchored name, each with a mutation. A probe with a deliberately generic `failsWith` is refused. The `open-redirect` scenario with the flag on fails with the new message, and with it off passes. A forced early stop leaves a table of the flags judged so far.

**Slice 2: the UI, the rules and the exit run** (`claude/cds-48-fix-ui-rules`).
- **A-04.** The `plural` call is wrapped in `TEST_BUILD`. The guard test asserts that every hyphenated UI flag is a marker; UI specification 6.8 and the guard comment are corrected. The public bundle is rebuilt and inspected.
- **A-05.** `progress-value-matches-text` also compares the drawn fill width with the value (clamped at 100). `chart-table-has-values` requires a number or "No score".
- **A-06.** `progress-name-matches-value` compares only the figures followed by `%`.
- **A-07.** A persona override with a summary over 280 characters, and an exit-run target that scans it folded and open (axe, the layouts). The exit run's expected counts change with it and are updated in the same pull request.
- *Proofs.* The hand-made pages from the review as unit-level probes (the width-only bar, the `n/a` cells, the fuller name each give the right answer). The real flags still fail their catchers.

**Slice 3: the visual check, one baseline refresh** (`claude/cds-48-fix-visual`).
- **B-05.** The profile tiles separate label and value. The accessible name each tile ends up with is checked, and a component test is added.
- **B-04.** The tab bar is hidden for the full-page shots (a style injected by the spec) and photographed once in a viewport-only shot at 375 px.
- **B-02.** The colour threshold is lowered (0.05 to 0.1). Stability is proved on Linux twice running and the red-to-amber probe locally. **If Linux flakes, I stop and bring the evidence to the owner before loosening anything.** The limit is restated in terms of hue and luminance.
- **B-03.** `fixtures/**` and `packages/api-client/**` are added to both path lists in `visual.yml`.
- **One refresh, one acceptance (D3).** Because B-05, B-04 and B-02 each change images, the baselines are made once by the manual workflow on the final code, and the refreshed images are shown to the owner before they merge.

**Slice 4: the report, the site and the workflows** (`claude/cds-48-fix-report-site`).
- **B-06.** The secret scans read every non-binary file as text. The report's file types are allow-listed under `report/`. `tok_[0-9a-f]{32}` is added to the token shapes. The claim in `site.ts` and DR-066 is reworded to what is checked. The reviewer's cases are the tests.
- **B-07.** The report check compares scenario names, and the rows per outline, against a manifest derived from the feature files (not hand-written), so a dropped or added scenario fails by name.
- **N-3.** The stamp check requires the full-length commit.
- **B-11.** `visual-baselines.yml`: the job that makes the images has no write token and `persist-credentials: false`; it uploads them as an artifact; a second job with `contents: write` pushes the branch and runs no project code. Protecting `main` stays a repository setting and the owner's.
- *Proofs.* Tests first with the reviewer's cases (a key in `report/notes.log`, `Bearer` in `report/x.md`, a `tok_` token, a base64 key if feasible, a dropped scenario plus an added row, a prefix stamp). Each fails before the fix and passes after, with mutations.

**Slice 5: the documents and the records** (`claude/cds-48-fix-docs`, then `claude/cds-48-records`).
- **B-12.** All seven corrections, with a note in harness design section 25 that section 31 supersedes its counts, and the `--update` first step for the local-try mode.
- **B-01 (the durable part).** The final proof table is taken from the `bug-flag-proof` artifact of the CI run on the final `main` commit, now with catcher output, and committed as `DOCS/evidence/phase-5-bug-flag-proof_<date>.md` with the run id and commit (D2). DR-067's reference points to it.
- Then the confirmation pass (D5: one fresh reviewer, Opus, blind, scoped to the fixes), DR-068 (what the review found and what it changes in DR-067's exceptions), the plan Outcome, the implementation log, backlog, CHANGELOG.

## Delivery

## Out of scope

The process-group kill of timed-out catchers (backlog); protecting `main`; the other Notes, as recorded; new Gherkin scenarios; the closure itself.

## Risks

- **Slice 3 is the riskiest.** A lower colour threshold may flake on Linux; the stop rule above covers it.
- **Slice 2 changes the exit run's counts and may flag a real page** under the new width rule; any such page is a finding to report, not to hide.
- **A new check can find a defect in a page that was fine before.** B-05 is an example; each such case is fixed or reported.
