# Implementation plan: CDS-17, auth-table backlog, Kanban board and Phase 1 closure

**History of this plan.** The owner was interviewed on four decisions on 2026-10-07. The plan was presented at 08:38Z (clock read at 08:38:39Z), approved, and written to this file at 08:58Z, before any implementation (DR-041).

**Goal.** The shared Kanban generator builds a board from this backlog, and CI fails on a stale board. Completing CDS-17 closes Phase 1 (decision brief 7 D1, DR-045).

## Evidence gathered before planning

A spike in the session scratchpad converted a copy of backlog v30 and ran the published generator against it. Nothing in the repository was changed.

| Finding | Consequence for the plan |
|---|---|
| The copy parses as 23 tickets: 16 Done, 1 Ready (CDS-17), 6 Backlog (CDS-18 to CDS-23) | The `auth-table` dialect works with `portfolio-kanban-generator` 1.2.0 (the current npm release) |
| The board is one self-contained HTML file of 19.9 KB, with no external `src` or `href` | Safe to commit; it opens offline |
| `--check` passes with the board or backlog in CRLF, and fails ("out of step") when CDS-17 is marked Done without regenerating | The drift gate works on Windows checkouts and catches a stale board |
| Ready and Backlog are derived from "Blocked by"; only Done and Parked are read from the backlog | Blockers must be explicit; the CDS-18 after CDS-17 order becomes a dependency |
| Phase grouping comes from `### Phase N` headings above the ticket tables | The summary becomes one table per phase |
| The registry's default `backlog_dialect` is already `auth-table`, and no portfolio tool reads this backlog's old status words | No registry change |

## Steps

1. **Backlog v31, summary.** The five-column table becomes tables under `### Phase 0` to `### Phase 3`, each shaped `| ID | Ticket | Type | Priority | Tier | Blocked by | Status |` with backticked IDs:
   - **Type**, from a fixed set: Decision, Specification, Behaviour, Tooling, Process, Service, Harness;
   - **Priority** `—`;
   - **Tier** HIGH, MEDIUM or LOW for open items (gate items HIGH), `—` when Done;
   - **Blocked by** as backticked IDs, with CDS-18 blocked by `CDS-17`.

   CDS-04 goes to Phase 1 (the pack's lint ruleset, and it serves the Phase 1 gate). CDS-11 goes to Phase 0 (specification content, done before the freeze).
2. **Status words.** COMPLETE becomes `Done <date>`, open items read `Open`, and nothing is Parked. A note says the backlog authors Done and Parked, and the board derives Ready and Backlog from "Blocked by". The status-vocabulary paragraph is rewritten. The Items sections are unchanged.
3. **Generator pinned.** `portfolio-kanban-generator` 1.2.0 becomes an exact root devDependency, with the lock updated. Root scripts: `kanban` writes the board; `check:kanban` runs `--check --dialect auth-table --backlog DOCS/backlog.md --project credit-dashboard-sut`.
4. **Board.** Generated and committed at the root as `credit-dashboard-sut_implementation-kanban_v1.html`, with header-only cards and no content override. Not published.
5. **Checks.** `tools/verify.mjs` gains a ninth step, the Kanban drift check. CI and the registry gate need no other change.
6. **Phase 1 closed.**
   - README: the 'SDD workflow' Phase 1 status reads Closed with the date and CDS-17; 'Status' is updated; 'What is here' gains a row for the board; 'Checks' mentions the drift check and `npm run kanban`.
   - Backlog: CDS-17 complete, Phase 1 closed. CHANGELOG.
   - No new DR: DR-045 already says Phase 1 closes with CDS-17.
7. **Records PR after merge:** this plan's Outcome, its index row, and an implementation log.
